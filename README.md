# Data Structures and Algorithms (DSA)

A learning repository for practicing **Data Structures and Algorithms using Java**. This repository is intended to build problem-solving skills, strengthen core programming concepts, and prepare for coding interviews through clear implementations and regular practice.

## 🎯 Goals

- Understand how common data structures work.
- Learn algorithm patterns and when to use them.
- Practice writing readable, maintainable Java solutions.
- Analyze time and space complexity.
- Build consistency with coding interview problems.

## 🧭 Topics to Practice

### 1. Java Fundamentals
- Variables, data types, operators, and control flow
- Methods, classes, and objects
- Arrays and strings
- Collections Framework: `ArrayList`, `HashMap`, `HashSet`, `Queue`, and `Stack`

### 2. Data Structures
- Arrays and strings
- Linked lists
- Stacks and queues
- Hashing
- Trees and Binary Search Trees
- Heaps and priority queues
- Graphs
- Tries and other structures as needed

### 3. Algorithm Patterns
- Searching and sorting
- Two pointers
- Sliding window
- Prefix sums
- Hash map and hash set techniques
- Recursion and backtracking
- Breadth-First Search (BFS) and Depth-First Search (DFS)
- Greedy algorithms
- Dynamic programming
- Graph algorithms

### 4. Problem-Solving Practice
For each problem, aim to:
1. Understand the problem and its constraints.
2. Identify the relevant data structure or pattern.
3. Develop a straightforward solution before optimizing it.
4. Test with examples and edge cases.
5. Explain the time and space complexity.

## 🛠️ Language and Tools

- **Language:** Java
- **Editor:** Visual Studio Code or any Java-compatible IDE
- **Version control:** Git and GitHub

## ▶️ Run a Java Program

Make sure a JDK is installed. From a terminal, compile and run a Java source file:

```bash
javac Main.java
java Main
```

The filename must match the public class name. For example, a file containing `public class Main` should be named `Main.java`.

## 📈 Learning Approach

- Practice consistently instead of rushing through many problems.
- Write down the key idea and common edge cases for each solution.
- Revisit problems and try to solve them without looking at the original code.
- Prefer correct, readable code before micro-optimizations.
- Track improvements in problem-solving and complexity analysis.
